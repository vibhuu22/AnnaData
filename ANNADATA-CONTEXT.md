# AnnaData — system context

A briefing document for an AI assistant with no prior knowledge of this project.
Everything below describes a system that exists and runs; figures marked
*measured* were taken from the running system.

> **Secrets are redacted.** Every credential appears as `<REDACTED>`. Do not
> paste real keys, passwords or tokens into a chat assistant.

---

## 1. What AnnaData is

An agricultural advisory service for Indian farmers. A farmer asks a question
about their own field, in their own language, through whatever channel they
have, and gets a specific, actionable answer.

Two things separate it from "a chatbot with a farming prompt":

1. **It reaches farmers without smartphones.** The primary channel is plain
   SMS, delivered through an Android handset acting as a gateway. No app, no
   data connection, no English literacy required.
2. **Figures that cost money are never generated by the model.** Pesticide
   doses come from the statutory CIB&RC register; support prices from a loaded
   MSP table; market rates from data.gov.in; land-unit conversions from a
   per-state table. Where there is no record, the answer says so rather than
   inventing a plausible number — and **code, not a prompt, enforces that**.

Scale today: **one farmer**. Everything below "does it behave correctly" is
unmeasured. Agronomic quality has not been reviewed by a qualified agronomist.

## 2. Channels

| Channel | How a farmer uses it | Identity |
|---|---|---|
| **SMS** | Texts a normal Indian mobile number | The sending phone number |
| **Web** | React app: sign-in, chat, voice, photo | Phone + one-time code, then a signed token |

a browser and later texts the gateway is *one* farmer with one history, not two

## 4. How an SMS reaches the system — the full path

This is the part most people get wrong, so it is spelled out end to end.

### 4.1 The physical transmitter

A **Samsung Galaxy Tab A (SM-T295)**, LTE variant, with a **Jio SIM**. It runs
SMS Gateway for Android (github.com/capcom6/android-sms-gateway). The tablet is
the actual radio: every reply is an ordinary SMS billed to that SIM.

The app runs in one of three modes. **AnnaData uses Cloud mode.**

| Mode | How the bridge reaches the handset | Needs |
|---|---|---|
| **Cloud** ← *in use* | Neither talks to the other directly; both talk to `api.sms-gate.app` | Handset has its own internet |
| Local | Bridge connects to the handset's HTTP server on the LAN | Same network (USB/Bluetooth tethering, or shared Wi-Fi) |
| Private | Self-hosted gateway server | Your own server |

**Consequence of Cloud mode, frequently misunderstood:** the handset needs
*only its own data connection*. It never connects to the developer's PC. USB or
Bluetooth tethering is **irrelevant** to the SMS path.

The handset must be charged, online, and exempt from battery optimisation.

### 4.2 Registration (done once)

The bridge registers a webhook with the gateway account:

```
event: sms:received
url:   https://<bridge-host>/incoming-sms
```

Registered per *account*, not per device, via `webhook.py`. The gateway API has
no PATCH for webhooks (it returns 404) — delete and recreate to change one.

### 4.3 Inbound, step by step

1. **Farmer texts the SIM number.** The mobile network delivers it to the tablet.
2. **The app posts to the cloud.** `api.sms-gate.app` receives it.
3. **The cloud calls the webhook** — `POST /incoming-sms` on the bridge, with a
   JSON payload containing `payload.messageId`, `payload.sender`,
   `payload.message`, `payload.receivedAt`.
4. **The bridge acknowledges within ~30s.** The gateway's webhook deadline is
   about thirty seconds, far shorter than an answer takes, so the handler
   returns `200` immediately and does the work in a background task:
   ```python
   asyncio.create_task(process_sms(data))
   return jsonify({"status": "ok"}), 200
   ```
5. **Filters, cheapest first**, before anything costs money:
   - **Deduplicate** on `messageId` (TTL `DEDUP_TTL`, default 600s). The cloud
     retries; without this a farmer is answered twice.
   - **Empty body / missing sender** → drop.
   - **`is_replyable(sender)`** — a sender we can answer is a phone number.
     Anything containing a letter (`JR-JIOPAY-S`, `VM-HDFCBK`) is a DLT machine
     ID and is dropped. One such message once reached the agent, was answered as
     a farming question, and was written to the farmer table — where it became
     permanently due for a rating request that could never be delivered.
   - **`is_operator_notice(message)`** — operator notices arrive from *numeric*
     shortcodes and survive the sender test. Content markers ("Dear Customer",
     "Team Jio", "missed call", OTP wording, bank debit/credit, recharge with a
     price attached) drop them. The marker list errs hard toward precision:
     letting spam through costs one model call, while a false positive silently
     swallows a farmer's question that they paid to send.
   - **STOP words** (`stop`, `band`, `band karo`, `unsubscribe`, `hatao`) →
     erase the farmer via `/forget` and confirm. This must work even when the
     agent is unreachable.
   - **A rating reply** (a bare number) → record it, thank them, stop. Checked
     before the agent, so "4" is not answered as a farming question.
6. **Call the backend.** `POST /agent` with:
   ```json
   {"query": "<verbatim text>", "channel": "sms",
    "user_id": "<phone>", "message_id": "<id>"}
   ```
   plus header `X-Bridge-Token: <REDACTED>`. The farmer's message is sent
   **verbatim** — brevity is requested via `channel`, never by appending
   instructions, because appended text was being parsed as part of the question
   and skewed crop and location extraction.
7. **Retry policy.** `AI_TIMEOUT` (default 150s) per attempt, `AI_ATTEMPTS`
   (default 2). The first attempt doubles as the wake-up call for a sleeping
   backend; by the retry it is usually warm. Waits grow between attempts.
8. **Format for SMS.** Markdown is flattened to plain text, then trimmed at a
   **sentence boundary** — never mid-word — to fit a budget counted in **billed
   segments**, not characters (see 4.4).
9. **Send the reply** via the gateway, from the same SIM.

### 4.4 Why segments, not characters

GSM-7 packs **153 characters per billed segment**. Devanagari, Gurmukhi, Telugu
and Bengali force UCS-2 at **67**. An identical-looking Hindi reply therefore
costs more than twice as much as an English one.

`MAX_SMS_SEGMENTS` (default 4) caps *segments* and is what actually controls
cost across languages; `MAX_SMS_CHARS` (default 480) is a hard character
ceiling. Capping by characters alone was measured to cost **2.3x more** per
segment for Indic scripts.

### 4.5 Regulatory note

Phone-as-gateway deliberately avoids India's **A2P/DLT regime**, which requires
a registered sender and pre-approved templates and would block free-form AI
replies outright. Correct at prototype stage; **wrong at scale**.

## 5. How one question is answered

A farmer texts *"Kapas me sundi lag gayi hai, kya spray karu?"*

1. **Bridge receives it** (section 4.3) and calls `/agent`.
2. **The backend decides who is calling** — bridge token, then signed token,
   then nobody (401 when `AUTH_REQUIRED`). Identity is the phone number on every
   channel, so one farmer has one history.
3. **Profile and history are recalled** — district, crops, land area, recent
   turns. Coordinates come from the profile when the request has none, which is
   what gives SMS access to location-aware tools.
4. **Refine and parse.** The question is resolved against the conversation, then
   **one** model call extracts crop, pest, state, location, intent and message
   kind together. Richer routing therefore costs **zero** extra calls.
5. **Plan.** `planner.py` maps intent to tools from a plain table — no model
   call. A pest question runs weather and the dose register; it does not fetch
   mandi prices for the whole state.
6. **Gather, concurrently.** Every selected *and configured* tool runs in
   parallel. A missing key means one tool reports itself unavailable — never a
   failed answer.
7. **Synthesise.** One model call, given today's date and where it falls in the
   Indian cropping calendar, the script the farmer wrote in, the channel's
   length budget, and the retrieved data.
8. **Guard.** `output_guards.py` deletes any sentence asserting a support price
   or scheme figure that nothing retrieved supports. Sentences naming the thing
   *without* a number survive — "ask at the sugar mill" is useful and true.
9. **Reply.** Returns `answer`, `reply_language`, `tools_used`, `intent`,
   `message_type`, `dose_status`, `missing_slots`, `session_id`.
10. **Remember.** What was learned goes into the profile; both messages are
    logged against the session, which is what later makes a rating interpretable.

**Three model calls per question.** The tools are the latency, not the model.

Photographs and voice notes take the same path via `/agent/media` in one round
trip. A transcript becomes the question verbatim; what a photograph showed fills
slots the words left empty — but the crop is the farmer's to state, and a
picture of one leaf does not get to correct them.

## 6. The refusals (the heart of the design)

Each exists because a prompt instruction was **not** enough.

- **A dose with nothing registered.** `pesticide_uses` is keyed on (crop, pest).
  No row means the answer names no product and no rate, and says why.
  `dose_status` is a field (`available` / `none_registered` / `not_applicable`),
  so an interface can render a refusal *as* a refusal rather than
  string-matching the word "registered" across four scripts.
- **A price with nothing behind it.** Asked for a support price it did not hold,
  the model wrote a fluent, specific, **invented** one — despite an explicit
  prohibition in the same prompt. Deterministic post-checks now strip those
  sentences.
- **A land unit that is not a unit.** A bigha is 0.31–1.25 acres depending on
  state — a factor of four, and a four-fold error in a pesticide quantity is
  exactly the harm the register grounding exists to prevent. `units.py` converts
  from a table and **refuses** when the state is unknown.
- **A disease the picture cannot settle.** The obvious build is a 29-class CNN
  over PlantVillage. It is the wrong tool because **a softmax cannot abstain**:
  it returns a confident class for a rice leaf it has never seen. Instead the
  photograph is read once into a closed symptom vocabulary and matched against
  labelled readings. The bank may only ever *weaken* a claim — `confirmed`,
  `disputed`, `uncovered`, `unavailable`. Where it disputes, the pest is
  dropped, no dose is looked up, and the farmer is sent to their KVK. The
  identification is hedged; the dose, from the statutory register, never is.
- **Retrieval outside coverage.** Passages below a measured cosine floor
  (`RAG_MIN_SIMILARITY`, 0.70) are never shown to the model. Covered questions
  score 0.68–0.80; uncovered top out near 0.58. Set too low, retrieval produces
  a *more confident guess*, not a grounded answer.
- **Claiming a capability that is down.** `provenance.py` assembles what the
  system can do from live state, because a hand-written self-description goes
  stale silently — it once told a farmer there were no scheme documents while
  the store held 86 passages about them.

## 9. Identity and privacy

- **Sign-in is a phone number plus a six-digit code**, carried afterwards in a
  signed token. `/agent`, `/agent/media`, `/profile` and `/history` take the
  farmer **from the token** and ignore what the body claims. Previously
  `user_id` arrived in the body and was believed — sound on SMS (the network
  vouches for the sender) but not on the web, where anyone could recall another
  farmer's profile and history into an answer, then write into their message log.
- **The code is never stored** — only a keyed hash bound to the phone it was
  issued for. Sends are throttled harder than guesses, because each one is a
  real SMS off a real SIM.
- **`AUTH_SECRET` does not degrade to "off".** Unset, a random one is generated
  per process: sign-in still works but a restart signs everyone out. A visible
  annoyance beats an invisible hole. `/health` reports which state you are in.
- **`/forget` erases a farmer** — profile and full message history — and backs
  the SMS STOP keyword.
- **`/feedback/*` require `BRIDGE_TOKEN`.** Where unset they stay open **and say
  so on `/health`** rather than closing: the services deploy separately, and a
  backend that starts 401ing a real farmer's SMS because a variable was missed
  is the worse failure.

## 11. Configuration

**Only `GEMINI_API_KEY` is required.** Every other integration is optional:
without it the tool reports itself unavailable, the agent routes around it, and
the advisory still goes out. `GET /health` reports exactly what is live.

| Variable | Unlocks | Without it |
|---|---|---|
| `GEMINI_API_KEY` | Everything | Service refuses to start |
| `AUTH_SECRET` | Sessions surviving a restart | Regenerated per process |
| `BRIDGE_TOKEN` | Proof the bridge is the bridge | `/feedback/*` stay open, reported on `/health` |
| `SMS_GATEWAY_USER` / `SMS_GATEWAY_PASSWORD` | Sending sign-in codes | Nobody can sign in on the web |
| `DATABASE_URL` | Profiles, history, doses, retrieval, lesion bank, ratings | Stateless: no memory, no grounded doses |
| `GOV_API_KEY` | Live mandi prices | MSP still answers |
| `EE_SERVICE_KEY` | Soil texture, pH, organic carbon | Advice omits soil |
| `LOCATION_API_KEY` | Google Maps geocoding | Nominatim used, needs no key |
| `KNOWLEDGE_BASE_ID` + AWS keys | Bedrock retrieval fallback | pgvector serves retrieval locally |
| `WHATSAPP_TOKEN` / `WHATSAPP_PHONE_NUMBER_ID` | WhatsApp channel | SMS and web only |
| `APP_USERNAME` / `PASSWORD` (bridge) | SMS channel | Web only |

Weather and geocoding need no key.

**Bridge-specific:** `SMS_MODE` (cloud/local/private), `AI_ENDPOINT`,
`PUBLIC_URL`, `WEBHOOK_PATH` (`/incoming-sms`), `DEDUP_TTL` (600),
`AI_TIMEOUT` (150), `AI_ATTEMPTS` (2), `SMS_TIMEOUT` (30),
`MAX_SMS_CHARS` (480), `MAX_SMS_SEGMENTS` (4), `STOP_WORDS`.

### Models

`gemini-2.0-flash` and the `gemini-2.5-*` line are no longer callable by new API
keys (404, pointing at the 3.x line). **`models.list` reports models a key
cannot actually invoke** — verify with a real `generateContent` call before
changing these.

- `TEXT_MODELS` = `gemini-3.1-flash-lite,gemini-3.6-flash,gemini-3.5-flash-lite`
- `MEDIA_MODEL` = `gemini-3.5-flash-lite`

The chain is fastest-first; a 429, 503 or 404 fails over to the next. The retry
budget is bound as a **call kwarg** on purpose — `langchain_google_genai`
otherwise defaults to six attempts with exponential backoff and stalls ~60s on a
dead model. Bound correctly, failover takes ~1s. Free-tier quota is **per
model**, so the chain also multiplies usable daily capacity.

**Binding constraint:** the free tier allows **20 `generateContent` requests per
day, per model**. At three calls per question that is roughly 20–30 questions a
day across the whole chain. Fine for testing, unusable in the field — enable
billing on the Google Cloud project behind the key before a pilot. Nothing in
the code changes; the same key simply stops being rate-limited.

## 12. Measured results

### Latency

| What | Before | After |
|---|---|---|
| Rice disease question, end to end | 97.4s | **4.0s** |
| Weather question, end to end | ~97s | **2.4s** |
| LLM failover past a dead model | 64.6s | **1.1s** |
| Soil lookup (3 Earth Engine reads) | ~9s | **1.5s** |
| Repeat weather, same district | 0.74s | ~0s (cache) |
| Price question during an upstream outage | 90.4s | ~0s after 3 failures (circuit breaker) |

Of the original 97.4s, **90.35s (92.8%)** was a dead data.gov.in. The three
model calls together were **6.1s**. This is why a master–worker architecture
would have made latency *worse*: the model calls were never the problem, and a
router plus per-domain workers multiplies the only part that was already fast.

Swapping the primary model from `gemini-3.6-flash` to `gemini-3.1-flash-lite`
took mean end-to-end answer time from **23.2s to 2.4s**, with answers still
correct and specific across Hinglish, Devanagari and English.

**Measured 2026-11-03 on the live Cloud Run deployment:**

- Warm `/agent`: **3.1s** (disease question), **16.5s** (greeting)
- Full SMS round trip, warm: **11–19s**
- Cold backend: **over 150s**, which exceeds the bridge's per-attempt timeout

### Efficiency

| | Before | After |
|---|---|---|
| Model calls per question | up to 4 | **3** |
| Tools run | all, always, sequentially | only what the intent needs, concurrently |
| Intent + message-kind + tool selection | a separate model call | **0 extra calls** |

### Grounding

| | |
|---|---|
| Registered pesticide uses | **2,456** across 314 crops and 825 products |
| Minimum Support Prices | 20 commodities, 39 aliases |
| Rows dropped by the misattribution guard | 256 of 2,722 |

| Defect | Magnitude |
|---|---|

store — OpenSearch Serverless Classic, billed a minimum of roughly
**$345–700/month** whatever it holds. Free tiers throughout: Render, Neon
Postgres with pgvector, Nominatim, Open-Meteo, MET Norway, Earth Engine
non-commercial, and the handset. The only item worth paying for is Gemini
billing, which is a quota question rather than an infrastructure one.

## 13. Operational characteristics and failure modes

Things that have actually gone wrong, and why.

- **Cold starts are the dominant operational risk.** Cloud Run scales to zero.
  Waking the backend (four ML models, Earth Engine init, Postgres pool) takes
  **over 150s**, exceeding the bridge's per-attempt timeout. The farmer's first
  message after a quiet spell is answered only because `AI_ATTEMPTS=2` absorbs
  the delay — measured at **3m22s** end to end. The `annadata-backend-warm`
  scheduler job exists precisely to prevent this.
- **Background work and CPU throttling.** The bridge returns 200 and then
  processes in an `asyncio` task. Cloud Run throttles CPU after a response
  unless `--no-cpu-throttling` is set, which makes post-response work
  unreliable.
- **Billing suspension takes everything down.** A closed billing account makes
  Cloud Run return 500/503 with *"The request failed because billing is disabled
  for this project"* before any code runs. After re-enabling, expect a transient
  period of **429 "aborted after waiting too long for an available instance"**
  while request-driven autoscaling re-provisions; it clears itself within
  roughly half an hour.
- **Webhook deliveries are not queued.** While the bridge was returning 500, the
  gateway retried about 15 times and then gave up. Messages sent during an
  outage are **lost**, not replayed.
- **Two generations in parallel.** Render runs a pre-sign-in build while Cloud
  Run runs current code. Check `/openapi.json` to tell which is which.
- **data.gov.in returns 502 for days at a time.** A circuit breaker stops
  farmers waiting out the timeouts.
- **Soil is a 250m global model**, not a test of the farmer's field. The system
  says so when asked.

## 15. Known limits

- **One farmer.** The rating loop, session features and eval harness all work.
  What is missing is people using the service.
- **Agronomic quality is unreviewed** by anyone qualified. This is the single
  largest gap.
- **A2P/DLT**: the phone-as-gateway design is right at prototype stage and wrong
  at scale.
- **CRA is unmaintained.** It builds today; Vite is the eventual path.
- **`.env.example` and `render.yaml` predate sign-in.** `AUTH_SECRET`,
  `BRIDGE_TOKEN`, `AUTH_REQUIRED`, `SMS_GATEWAY_*`, `RAG_MIN_SIMILARITY` and the
  WhatsApp variables must be set by hand.
- **Operator-notice filtering is a curated list, not a classifier.** New
  phrasings will slip through; each is a one-line addition plus a test case.

## 16. Glossary

| Term | Meaning |
|---|---|
| **CIB&RC** | Central Insecticides Board and Registration Committee — India's statutory pesticide register |
| **MSP** | Minimum Support Price — government floor price for a commodity |
| **Mandi** | Government-regulated agricultural market; mandi prices are local spot rates |
| **KVK** | Krishi Vigyan Kendra — district-level farm science centre; the human escalation path |
| **DLT** | India's registry regime for application-to-person SMS senders and templates |
| **GSM-7 / UCS-2** | SMS encodings: 153 versus 67 characters per billed segment |
| **Rabi / Kharif** | Winter-sown and monsoon-sown cropping seasons |
| **Bigha** | Regional land unit, 0.31–1.25 acres depending on state |
| **pgvector** | Postgres extension for vector similarity search |
| **Lesion bank** | Labelled symptom readings used for photo diagnosis by agreement, not classification |
